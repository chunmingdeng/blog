# webAssembly base

WebAssembly（Wasm）技术已经走出了“浏览器玩具”的早期阶段，其应用场景覆盖了从前端到后端、从边缘计算到区块链的多个领域。核心价值在于接近原生的性能和跨平台的安全沙箱。

以下是几个关键的应用场景和具体案例：

## 一、 浏览器内的重型计算
这是 Wasm 最初的使命，让 web 应用打破 JavaScript 的性能天花板。

图形与视频编辑
在浏览器里实现高性能的图像滤镜、实时视频剪辑和特效渲染，处理大分辨率的图层和复杂的编码解码，远超纯 JS 的性能。

案例：Figma 使用 Wasm 加载和渲染大型设计文件，加载速度提升近3倍。Photoshop 网页版和 Shapr3D（CAD建模） 也都将核心计算引擎编译为 Wasm 运行。

游戏引擎
将使用 C++、Rust 编写的成熟游戏引擎部署到浏览器，无需插件，体验接近原生。

案例：Unity 和 Unreal Engine 都能将项目导出为 Wasm。许多经典游戏（如《毁灭战士3》）也因此能在浏览器中流畅运行。

音视频编解码
利用 Wasm 运行用 C 编写的强大编解码器（如 FFmpeg），支持浏览器不原生支持的格式。

案例：Google Meet 使用 Wasm 进行实时视频背景模糊和替换，效果优于基于 WebGL 的方案。Spotify 用它高效解码音频流。

科学计算与数据可视化
在浏览器本地运行物理、化学模拟，或处理大规模数据集进行图表渲染。

案例：Google Earth 将 C++ 渲染引擎编译为 Wasm 在浏览器中运行。Observable 等平台也支持 Wasm 加速数据处理。

## 二、 边缘计算与 Serverless
这里的 Wasm 作为轻量级、快速启动、强隔离的运行时，挑战容器的主导地位。

内容分发网络（CDN）边缘定制
在靠近用户的 CDN 节点上运行自定义代码，实现个性化、安全鉴权、A/B 测试等功能。Wasm 毫秒级的冷启动速度特别适合这种请求量波动大的场景。

案例：Cloudflare Workers 及其后续的 Workers AI（在边缘运行AI模型）都基于 Wasm 运行时。Fastly Compute@Edge、AWS Lambda（通过自定义运行时）和 阿里巴巴的CDN边缘脚本也都支持 Wasm。

服务网格与API网关
在数据面代理中，用 Wasm 安全地执行自定义的扩展插件，如流量控制、认证、日志记录。

案例：Envoy 和 Istio 项目原生支持 Wasm 插件，代替了不安全的原生代码扩展。Apache APISIX 也深度集成了 Wasm。

物联网与嵌入式设备
Wasm 占用资源少、跨平台、多语言支持，很适合在资源受限的 ARM 设备上运行安全的微服务逻辑。

案例：Android 系统通过 WasmEdge 等运行时直接在系统服务中运行 Wasm 模块。

## 三、 跨平台应用开发
用同一套 Rust/C++ 核心逻辑，编译为原生库和 Wasm，在不同平台复用代码。

桌面应用
使用 Electron 等框架构建的桌面应用，可将性能敏感模块用 Wasm 实现，在渲染进程中安全地运行原生级代码。

案例：1Password 桌面版的核心加密和数据处理逻辑使用 Rust 编写，并编译成 Wasm 在 Electron 内运行，保证了核心代码在桌面和 Web 端完全一致。

移动应用
在 iOS 和 Android 应用中，通过 WKWebView 或 JSCore/V8 运行 Wasm，共享与 Web 端相同的核心业务逻辑。

## 四、 区块链与智能合约
Wasm 为智能合约提供了比以太坊虚拟机（EVM）更强大的性能和灵活性，同时保持确定性执行。

高性能智能合约
开发者可用 Rust、C/C++ 等主流语言编写复杂的、计算密集型的链上逻辑。

案例：Polkadot、NEAR、EOS、Solana 等公链，以及 Hyperledger Fabric 联盟链，都采用 Wasm 作为智能合约引擎。

## 五、 数据与集成
替代传统 ETL 工具中的脚本语言，提供统一的、安全的、可移植的转换逻辑。

数据管道
在数据库内部或数据流处理平台中，直接用 Wasm 运行用户自定义函数（UDF）。

案例：Redpanda（流处理平台）和 SingleStore 数据库都支持 Wasm 作为 UDF 运行环境。Figma 甚至用 Wasm 作为其插件系统的沙箱，提供高安全性和可移植性。
